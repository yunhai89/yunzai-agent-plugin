## 🧬 工具进化（Tool Evolution）

> Agent 不再只从固定工具列表中选择——它能**生成新工具、验证、审批上线、持续改进与淘汰**，形成可演化的工具库。这是本插件相对普通 Agent 框架的核心差异点，也是搜索词 `tool evolution agent` 的入口。

**完整生命周期**（安全纵深，五阶段）：

```
#进化工具 <能力描述>
  → LLM 生成（json_schema 结构化）
  → typescript AST 静态门（禁 require / child_process / process.env / eval / 一切 import；危险候选不入库）
  → 隔离行为验证（E2B 沙箱 / 本地子进程双档 + 测试断言 + 性能/超时门）
  → #采纳工具 <id>（master 审批）→ stable + 注入 → agent 直接调用（工具定义全量常驻）
  → 调用埋点 → 适应度 / 失败聚类 → #工具健康 检测 → #进化工具 修复 <工具名> <描述> 生成改进候选 → #回滚工具 切回旧版 / #淘汰工具 下线
```

改进候选会**继承父版本测试**（回归护栏）；Web 面板可展开「详情」审阅源码、测试用例与验证证据。

**安全原则**（不可妥协）：
- ① **生成闸**：只允许 `sideEffects ∈ {none, read}`；联网 / 发消息 / 删库等**固定受信适配器永不自动生成**
- ② **可信基不可被工具进化**：DB / 验证器 / 沙箱 / 审批 / 审计由人维护，工具不能改
- ③ **版本不可变 + 审计 + 权限单调不增 + 安全硬否决**（一票否决，非权重）
- ④ **内置/受信工具不可被进化状态机改写或回滚**；进化工具名不得占用已注册内置/Meta/MCP 工具名
- ⑤ **采纳前可审阅**：Web 详情展示源码、测试用例、验证证据与哈希；`stable` 仍只允许 verified 版本手动审批

**命令族**（均 master）：`#进化工具` / `#进化工具 修复 <工具名> <修复描述>` / `#工具进化列表` / `#采纳工具` / `#淘汰工具` / `#回滚工具` / `#工具健康` + Web「工具进化」管理面板。
